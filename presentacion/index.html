Bloque 4

EC2: el backend como servicio

  1. Lanzar Amazon Linux 2023 con sg-backend.
  2. Instalar Java 17 (Corretto).
  3. Subir app.jar con scp.
  4. Guardar las variables en /etc/app.env (modo 600).
  5. Crear el servicio systemd y activarlo.

[Service]

User=ec2-user

EnvironmentFile=/etc/app.env

ExecStart=/usr/bin/java -Xmx512m \

-jar /home/ec2-user/app.jar

Restart=on-failure

DSY1104 · Taller de despliegue en AWS

9 / 15

El servicio arranca solo si la instancia se reinicia, algo que ocurre al cerrar y reabrir el laboratorio. -Xmx512m evita que la JVM consuma toda la memoria de una instancia pequeña.

Bloque 5

S3: el frontend como archivos

  1. Compilar con la URL del backend.
  2. Crear el bucket y quitar el bloqueo de acceso público.
  3. Activar Static website hosting con index.html.
  4. Aplicar la política de lectura pública.
  5. Subir el contenido de dist/.
  6. Actualizar CORS_ORIGIN en EC2 y reiniciar.

VITE_API_URL=http://<IP>:8080 \

npm run build

sudo systemctl restart app

Bloque 7

Limpieza de recursos

  1. Vaciar y eliminar el bucket.
  2. Terminar la instancia EC2.
  3. Eliminar la base en RDS.
  4. Eliminar sg-rds y luego sg-backend.
  5. Eliminar el par de claves.
  6. Revisar el gasto al día siguiente.

RDS sigue cobrando con el laboratorio cerrado.

Entrega

Checklist de evidencias

  • URL del frontend en S3.
  • Endpoint GET del backend con JSON.
  • Reglas de sg-backend y sg-rds.
  • RDS con Public access: No.
  • systemctl status app en ejecución.
  • Consola sin errores de CORS.
  • Repositorio sin secretos.
  • Recursos eliminados o detenidos.
